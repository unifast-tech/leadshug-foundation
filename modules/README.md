## Future module schema

A new or materially evolved module document must state its ownership boundary, invariants, stable capabilities, local contracts/API definitions, dependencies, and links to relevant decisions/TODO evidence. Its local facts remain singular in the module; other Foundation surfaces link to it rather than copying them.

New modules require a separately approved TODO and a clear ownership boundary. This README does not migrate or assert maturity for the current individual module documents.
